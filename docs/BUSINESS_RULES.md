## 0. بنية البيانات في التطبيق القديم

*المصدر: `seedData`، و`sanitizeData`، و`sanitizeExp`، و`sanitizeState`*

```
state
├── schemaVersion: 3
├── currentId                       ← "الشخص" المفتوح حالياً
└── profiles[]                      ← "الأشخاص" (تصير budgets في M-SAL2.0)
    ├── id, name
    └── data
        ├── monthLabel              ← اسم الشهر
        ├── salaryLabel             ← مسمى الراتب (افتراضياً "الراتب")
        ├── salary                  ← نص (قد يبدأ بـ ~)
        ├── blocks[]                ← المجموعات
        │   ├── id, title
        │   └── rows[]  { id, name, amount (نص), done }
        └── exp                     ← قسم المصاريف
            ├── accounts[]  { id, name, archived, cycles[] }
            │                 cycles[] { id, startDate, allowance, expectedNextSalaryDate? }
            ├── lastAccountId
            ├── categories[] { id, name, emoji, hidden }
            └── entries[]   { id, type, amount, name, categoryId, date, accountId,
                              createdAt, updatedAt?, deletedAt? }
```

**ملاحظات مهمة:**
- **الدورات تابعة للحساب**، فكل حساب له دوراته الخاصة.
- **الفئات والحسابات والمصاريف تابعة "للشخص"**، وليست عامة.
- **مبلغ الدورة منفصل تماماً عن دفتر الميزانية.** قسم الميزانية وقسم المصاريف لا يؤثر أحدهما على الآخر.

## 1. قواعد عامة

### R-GEN-01: التقريب
*المصدر: `roundMoney`، و`sumMoney`*
- كل مبلغ يُقرّب إلى **خانتين** بعد كل عملية: `round((n + EPSILON) × 100) / 100`.
- في M-SAL2.0 نستخدم `BigDecimal` بخانتين (`Money.round`): النصف يُقرَّب للأعلى (`HALF_UP`) للموجب، ونحو الصفر للسالب (`-1.005` يصير `-1.00`)، لأن `Math.round` في JavaScript يقرّب النصف نحو +∞. هكذا تطابق الأرقام التطبيق القديم تماماً.

### R-GEN-02: التواريخ
*المصدر: `formatDate`، و`parseDate`، و`todayStr`*
- الصيغة `YYYY-MM-DD` حسب **التوقيت المحلي** للمستخدم، وليس UTC.
- في M-SAL2.0: "اليوم" يُحسب بتوقيت المستخدم (افتراضياً `Asia/Dubai`)، وليس بتوقيت السيرفر.

### R-GEN-03: الحذف المؤقت
- أي سجل فيه `deletedAt` **لا يدخل في أي حساب أو عرض**، إلا صفحة "المحذوفات".

### R-GEN-04: الأرقام العربية في الإدخال
*المصدر: `toLatinDigits`، و`normalizeDigits`*
- الأرقام العربية `٠-٩` والفارسية `۰-۹` تتحول إلى `0-9`.
- الفاصلة العشرية العربية `٫` تتحول إلى `.`، وفاصل الآلاف `٬` يُحذف.

### R-GEN-05: عرض المبالغ
*المصدر: `formatMoney`، و`AED`*
- عدد صحيح بدون كسور: `46` و`1,200`.
- مع كسور تظهر خانتان دائماً: `46.50`.
- الأرقام **لاتينية دائماً**، والعملة `د.إ`.

### R-GEN-06: عرض التاريخ
*المصدر: `dayLabel`، و`fullArabicDate`، و`shortArabicDate`*
- "اليوم" و"أمس" و"غدًا" للأيام القريبة.
- غير ذلك: `الأحد 11 نوفمبر 2026` (كامل)، أو `11 نوفمبر` (مختصر).

## 2. الميزانية الشهرية (SRV-002)

### R-BUD-01: حساب "المتبقي"
*المصدر: `computeTotals`*

```
المتبقي = الراتب − مجموع المجموعة 1 − مجموع المجموعة 2 − ...
```

- **كل مجموعة** تعرض: "المجموع" (مجموع بنودها)، و"المتبقي بعده" (الرصيد بعد خصم هذه المجموعة وكل ما قبلها).
- **علامة "تم الصرف" (`done`) لا تؤثر على الحساب أبداً.** هي للمتابعة فقط.
- **المتبقي ممكن يكون سالباً**، ويُعرض بلون التحذير.

**مثال:**
```
الراتب: 15,000
المجموعة 1 "التزامات ثابتة": إيجار 5,000 + كهرباء ~400   ← المجموع ~5,400
                                                         ← المتبقي بعده ~9,600
المجموعة 2 "أقساط": سيارة 2,500                          ← المجموع 2,500
                                                         ← المتبقي بعده ~7,100
المتبقي النهائي: ~7,100
```

### R-BUD-02: المبالغ التقريبية (~)
*المصدر: `parseAmount`، و`computeTotals`*
- المبلغ الذي يبدأ بـ `~` يعني "تقريبي"، مثل الكهرباء التي تتغير كل شهر.
- **المجموعة** تصير تقريبية إذا فيها بند تقريبي واحد على الأقل.
- **"المتبقي بعده"** يصير تقريبياً إذا الراتب أو أي مجموعة قبله أو هذه المجموعة تقريبية. التقريب **ينتقل للأسفل** ولا يرجع.

### R-BUD-03: إدخال مبالغ الميزانية
*المصدر: `parseAmount`، و`canonicalRaw`*
- الأرقام العربية تتحول (R-GEN-04)، والفواصل والمسافات تُحذف.
- **النص غير الصالح يُحسب 0**، والحقل الفارغ يُحسب 0.
- **السالب مسموح هنا** (مختلف عن المصاريف).
- أثناء الكتابة يُعرض النص كما هو، وبعد الخروج من الحقل يُنسّق: `1234.5` يصير `1,234.5`.

### R-BUD-04: المجموعات والبنود
*المصدر: `btnAddBlock`، و`renderBlock`، و`renderRow`*
- **مجموعة جديدة** تأتي ببند واحد فارغ.
- **بند جديد:** اسم فارغ، ومبلغ فارغ، و`done = false`.
- **حذف بند:** فوري بدون تأكيد.
- **حذف مجموعة فيها محتوى:** يطلب تأكيداً "حذف المجموعة «X» وكل بنودها؟". والمجموعة الفارغة تُحذف فوراً.
- المجموعات مرقّمة تلقائياً `01`، `02`، ... حسب ترتيبها، والراتب رقمه `00`.

### R-BUD-05: شهر جديد
*المصدر: `btnNewMonth`*
- يطلب تأكيداً.
- **يمسح علامات "تم الصرف"** من كل البنود.
- **يغيّر اسم الشهر** إلى اسم الشهر الحالي (`defaultMonthLabel`).
- **البنود والمبالغ تبقى كما هي.**

### R-BUD-06: الميزانيات ("الأشخاص")
*المصدر: `addProfile`، و`btnDeleteProfile`، و`seedData`*
- **ميزانية جديدة** تحتاج اسماً، وتبدأ بـ: اسم الشهر الحالي، و"الراتب"، ومجموعة واحدة "التزامات ثابتة" فيها بند فارغ، وقسم مصاريف بالحساب والفئات الافتراضية.
- **لا يمكن حذف آخر ميزانية.**
- **الحذف نهائي** ويطلب تأكيداً.
- الاسم الافتراضي عند عدم وجود أي ميزانية: "الأساسي". والاسم الفارغ يصير "بدون اسم".

## 3. دورات الراتب (SRV-003)

### R-CYC-01: متى تبدأ دورة الراتب ومتى تنتهي؟
*المصدر: `sortCycles`، و`cycleForDate`، و`cycleBounds`، و`bucketEntries`*

- الدورة **تبدأ** في التاريخ الذي يُسجَّل فيه "وصل الراتب" (`startDate`).
- الدورة **تنتهي** في اليوم الذي يسبق بداية الدورة التالية (`lastDay = بداية التالية − يوم`).
- **آخر دورة** تبقى "مفتوحة" (`open`) حتى تُسجَّل الدورة التالية.
- **أي مصروف** ينتمي لآخر دورة بدأت في تاريخه أو قبله، **في نفس الحساب**.
- الدورات تُرتّب حسب تاريخ البداية، وعند التساوي حسب `id`.
- المصاريف التي تاريخها **قبل أول دورة** تذهب إلى "بدون دورة" (`noCycle`)، والتي تاريخها غير صالح تُعرض أيضاً مع "بدون دورة" ولا تُخفى أبداً.
- **لا يضيع أي مصروف أبداً**: كل مصروف يقع في مجموعة واحدة بالضبط.
- **الانتماء للدورة لا يُحفظ في المصروف**، بل يُحسب من التاريخ دائماً.

**مثال:**
```
دورة أ تبدأ 2026-10-01، ودورة ب تبدأ 2026-11-01
← دورة أ: من 2026-10-01 إلى 2026-10-31
← دورة ب: من 2026-11-01، ومفتوحة
← مصروف بتاريخ 2026-10-15 ينتمي لدورة أ
← مصروف بتاريخ 2026-09-20 يذهب إلى "بدون دورة"
```

### R-CYC-02: الدورة الجديدة ("وصل الراتب")
*المصدر: `prefillNewCycle`، و`addCycle`، و`cleanAllowance`*
- التاريخ الافتراضي = **اليوم**.
- المبلغ الافتراضي = **مبلغ آخر دورة**، أو 0 إذا لا توجد دورات.
- بعد الحفظ تظهر رسالة "بدأت دورة جديدة من 1 نوفمبر 2026".

### R-CYC-03: التحقق عند حفظ الدورة
*المصدر: `openCycleSheet.save`، و`parseAllowance`، و`validateCycleDate`*

| الشرط | رسالة الخطأ |
|---|---|
| التاريخ غير صالح | "اختر تاريخًا صحيحًا." |
| المبلغ فارغ أو غير صالح | "أدخل مبلغًا صحيحًا للمخصَّص (يمكن أن يكون 0)." |
| تاريخ الراتب القادم ليس **بعد** بداية الدورة | "تاريخ الراتب القادم يجب أن يكون بعد بداية الدورة." |
| توجد دورة أخرى بنفس التاريخ | "توجد دورة أخرى بنفس هذا التاريخ. اختر تاريخًا مختلفًا أو عدّل تلك الدورة." |

- **المبلغ:** الفارغ مرفوض، و`0` أو `000` مقبول (يساوي 0)، وغير ذلك يتبع قواعد مبلغ المصروف (R-ENT-03).
- **تاريخ الراتب القادم اختياري**، وفيه زر "مسح الراتب القادم".

### R-CYC-04: كيف تُحسب "كم تقدر تصرف اليوم"؟
*المصدر: `cycleSummary`*

```
المتبقي في بداية اليوم = مبلغ الدورة + الدخل قبل اليوم − المصاريف قبل اليوم
الأيام الباقية         = من اليوم حتى تاريخ الراتب المتوقع (يوم واحد على الأقل)
ميزانية اليوم          = (المتبقي في بداية اليوم ÷ الأيام الباقية) + دخل اليوم
تقدر تصرف اليوم       = ميزانية اليوم − ما صرفته اليوم
```

إذا كان الناتج سالباً:
```
التجاوز اليوم = −(تقدر تصرف اليوم)
ميزانية بكرة  = (المتبقي في بداية اليوم + دخل اليوم − ما صرفته اليوم) ÷ (الأيام الباقية − 1)
                ← تُحسب فقط إذا كانت الأيام الباقية أكثر من 1
```

**مثال:** مبلغ الدورة 3,000. بدأت 2026-11-01، والراتب المتوقع 2026-12-01. اليوم 2026-11-11.
```
صرفت قبل اليوم:        1,000
المتبقي بداية اليوم:   3,000 − 1,000 = 2,000
الأيام الباقية:        من 2026-11-11 إلى 2026-12-01 = 20
ميزانية اليوم:         2,000 ÷ 20 = 100.00
صرفت اليوم 30          ← تقدر تصرف 70.00
صرفت اليوم 150         ← التجاوز 50.00، وميزانية بكرة = (2,000 − 150) ÷ 19 = 97.37
```

**تفاصيل يجب الحفاظ عليها:**
1. **ميزانية اليوم ثابتة طوال اليوم.** تُحسب من رصيد **بداية اليوم**، فلا تتغير مع كل مصروف.
2. **المصاريف بتاريخ مستقبلي** لا تدخل في حساب اليوم.
3. يُحسب **فقط للدورة المفتوحة** التي لها **تاريخ راتب متوقع** بعد بدايتها. غير ذلك القيمة فارغة (`null`).
4. **الدخل الذي يصل اليوم** يُضاف لميزانية اليوم كاملاً، ولا يُقسَّم على الأيام.
5. **في العرض:** ميزانية اليوم تُعرض بحد أدنى 0، وشريط التقدم = صرفت اليوم ÷ ميزانية اليوم (ممتلئ عند التجاوز).

### R-CYC-05: ملخص الدورة
*المصدر: `cycleSummary`*

| القيمة | الحساب |
|---|---|
| المصروف (`spent`) | مجموع المصاريف (كل ما ليس `income`) في الدورة |
| الدخل الإضافي (`extra`) | مجموع الدخل (`income`) في الدورة |
| الميزانية (`budget`) | مبلغ الدورة + الدخل الإضافي |
| المتبقي (`remaining`) | الميزانية − المصروف |
| التقدم (`progress`) | المصروف ÷ الميزانية، بحد أقصى 1. وإذا الميزانية 0: يساوي 1 إذا يوجد مصروف، وإلا 0 |
| الأيام المنقضية (`daysElapsed`) | من البداية حتى اليوم أو آخر يوم في الدورة (الأقرب)، شاملاً اليومين. يساوي 0 إذا لم تبدأ بعد |
| إجمالي الأيام (`totalDays`) | دورة مغلقة: من البداية حتى بداية التالية. دورة مفتوحة: حتى تاريخ الراتب المتوقع، وإلا فارغ |
| المتوسط اليومي (`dailyAverage`) | المصروف ÷ الأيام المنقضية (يوم واحد على الأقل) |
| متجاوز (`over`) | المتبقي أقل من 0، ويظهر "تجاوزت المتاح" |

### R-CYC-06: ما يُعرض في الرئيسية حسب حالة الدورة
*المصدر: `renderHome`، و`renderHero`، و`renderDaily`*

| الحالة | ما يظهر |
|---|---|
| دورة مفتوحة مع تاريخ راتب متوقع | بطاقة "تقدر تصرف اليوم"، أو "تجاوزت اليوم" مع "بكرة تقدر تصرف"، وعدد الأيام الباقية |
| دورة مفتوحة بدون تاريخ راتب متوقع | زر "حدّد تاريخ الراتب القادم لتعرف كم تقدر تصرف كل يوم" |
| دورة مغلقة (قديمة) | "متوسط الصرف اليومي" و"مدة الدورة" |
| "بدون دورة" | مجموع مصاريفها، وزر "إضافة دورة سابقة" يقترح تاريخ **أقدم مصروف** ومبلغ 0 |
| لا توجد دورات أصلاً | "ابدأ دورتك الأولى"، مع شرح أن الدورة تمتد من الراتب للراتب، وليس من أول الشهر |

- **آخر المصاريف:** أحدث 5 مصاريف في الدورة المختارة، مع زر "عرض الكل".
- **الدورة المختارة افتراضياً** هي آخر دورة. وعند إضافة أو تعديل مصروف، ينتقل العرض إلى دورة ذلك المصروف.

### R-CYC-07: تغيير تاريخ بداية الدورة
*المصدر: `setCycleDate`، و`movedEntryCount`، و`openCycleSheet.showImpact`*
- **المصاريف نفسها لا تتغير أبداً.** الذي يتغير هو حدود الدورات، فينتقل الانتماء تلقائياً حسب R-CYC-01.
- **قبل الحفظ** يُعرض عدد المصاريف التي ستنتقل بين الدورات:
  - "بهذا التغيير ستنتقل 3 من المصاريف بين الدورات تلقائيًا."
  - أو "لن تنتقل أي مصاريف بين الدورات."
- العدد يحسب كل مصروف (غير محذوف) يتغير مكانه، بما فيها الانتقال من أو إلى "بدون دورة".

**مثال:**
```
دورة أ: 2026-10-01، ودورة ب: 2026-11-01
مصاريف بتاريخ 10-28، و10-30، و11-02
تغيير بداية ب إلى 2026-10-28
← مصروفا 10-28 و10-30 ينتقلان من أ إلى ب  ← "ستنتقل 2 من المصاريف"
```

### R-CYC-08: حذف الدورة
*المصدر: `openCycleSheet` (زر "حذف الدورة")*
- يطلب تأكيداً: "حذف هذه الدورة؟ مصاريفها لن تُحذف، بل ستنتقل تلقائيًا إلى الدورة السابقة (أو «بدون دورة»)."
- **المصاريف لا تُحذف أبداً.** تنتقل للدورة السابقة، أو إلى "بدون دورة" إذا كانت الأولى.

## 4. المصاريف (SRV-001)

### R-ENT-01: المصروف
*المصدر: `newEntry`*
- النوع: `expense` (مصروف) أو `income` (دخل إضافي).
- الحقول: المبلغ، والوصف، والفئة، والتاريخ، والحساب، ووقت الإنشاء.
- **الاسم المعروض** = الوصف، أو اسم الفئة إذا الوصف فارغ (للبيانات القديمة).
- الدخل يُعرض بعلامة `+`.

### R-ENT-02: التحقق قبل الحفظ
*المصدر: `canSaveEntry`، و`openEntrySheet.commit`*

بالترتيب:

| الشرط | رسالة الخطأ |
|---|---|
| المبلغ غير صالح | "أدخل مبلغًا صحيحًا أكبر من صفر." |
| لا توجد فئة | "اختر تصنيفًا." |
| الوصف فارغ (المسافات وحدها لا تكفي) | "اكتب وصف"، ويهتز الحقل |
| التاريخ غير صالح | "تاريخ غير صالح." |

- زر الحفظ يبدو معطلاً حتى تكتمل البيانات، لكنه يستجيب للضغط ويعرض سبب المنع.

### R-ENT-03: إدخال مبلغ المصروف
*المصدر: `parseEntryAmount`*
- الأرقام العربية تتحول (R-GEN-04)، والمسافات تُحذف.
- **إذا يوجد `.`** تُحذف كل الفواصل `,`.
- **إذا لا يوجد `.`** وفيه فاصلة واحدة بعدها خانة أو خانتان، تُعتبر الفاصلة عشرية. غير ذلك تُحذف الفواصل.
- **المبلغ يجب أن يكون أكبر من 0 وأقل من أو يساوي 999,999,999.**
- يُقرّب إلى خانتين، وإذا صار 0 بعد التقريب يُرفض.

| الإدخال | النتيجة |
|---|---|
| `٤٦٫٢٥` | 46.25 |
| `46,25` | 46.25 |
| `1,234.50` | 1234.50 |
| `1,234` | 1234 |
| ` 12 ` | 12 |
| `0` | ❌ مرفوض |
| `-5` | ❌ مرفوض |
| `0.001` | ❌ مرفوض (يصير 0 بعد التقريب) |
| `abc` | ❌ مرفوض |

### R-STA-02: التوزيع حسب الفئة
*المصدر: `categoryTotals`*

**مثال:**
```
أكل 10، وبقالة 10، وبنزين 10  ← 33.33% لكل واحدة
التقريب للأسفل: 33 + 33 + 33 = 99  ← الفرق 1 يذهب للأولى
النتيجة: 34%، 33%، 33%
```

## 10. ملاحظات لجلسة التخطيط 2 (قاعدة البيانات)

اكتُشفت أثناء استخراج القواعد:

1. **التبعية:** المستخدم ← الميزانيات (budgets) ← الحسابات والفئات والمصاريف ← الدورات تابعة للحساب.
2. **مبالغ الميزانية الشهرية** نص قد يكون تقريبياً (`~`) أو سالباً ← عمودان: `amount numeric(12,2)` و`is_approx boolean`، والحقل الفارغ `null`.
3. **مبالغ المصاريف ومبلغ الدورة** دائماً أرقام موجبة (والدورة تقبل 0) ← `numeric(12,2)` مع `CHECK`.
4. **معرّفات التطبيق القديم** مثل `acc_main` و`cat_food` وقيم `uid()` ← عمود `legacy_id` لتعمل طريقة "الدمج" عند الاستيراد، ولا تتكرر البيانات إذا استُورد الملف مرتين.
5. **الفئات الافتراضية** تُنسخ لكل ميزانية جديدة، مع عمود `code` (مثل `cat_food`) لربط الاقتراحات الافتراضية.
6. **قيد فريد:** `(account_id, start_date)` في `salary_cycles`.
7. **ترتيب الفئات** ← عمود `sort_order`. **ترتيب المجموعات والبنود** ← عمود `sort_order` أيضاً.
8. **`createdAt` في التطبيق القديم** بالمللي ثانية ← `timestamptz` عند الاستيراد.
9. **الانتماء للدورة لا يُخزَّن** في جدول المصاريف، بل يُحسب من التاريخ (R-CYC-01).
10. **المنطقة الزمنية للمستخدم** ← عمود `time_zone` في `app_users` (افتراضياً `Asia/Dubai`) لحساب "اليوم".
