## 1. القواعد العامة

| القاعدة | القيمة |
|---|---|
| **العنوان الأساسي** | `https://<render-domain>/api/v1` (محلياً `http://localhost:8080/api/v1`) |
| **الصيغة** | JSON، وأسماء الحقول بأسلوب `camelCase` |
| **تسجيل الدخول** | `Authorization: Bearer <JWT من Supabase>` في كل طلب |
| **المعرّفات** | UUID كنص |
| **التواريخ** | `"2026-11-11"` (بدون وقت) |
| **الأوقات** | ISO-8601 بتوقيت UTC: `"2026-11-11T08:14:02Z"` |
| **المبالغ** | **نص** وليس رقماً: `"46.25"`، حتى لا تضيع الهللات في JavaScript |
| **"اليوم"** | يحسبه السيرفر بتوقيت المستخدم (`app_users.time_zone`)، ويرجعه في الردود التي تحتاجه كحقل `today` |
| **الإصدار** | `/v1` في العنوان. أي تغيير يكسر Angular يصير `/v2` |
| **تتبع الطلب** | كل رد فيه الهيدر `X-Request-Id`، ونفس القيمة تظهر في السجلات و`audit_log` |
| **التوثيق التلقائي** | springdoc-openapi يولّد صفحة Swagger، **في بيئة التطوير فقط** |

### إدخال المبالغ: من يحلّل ماذا؟

| | Angular | Spring Boot |
|---|---|---|
| **قواعد الإدخال** (الأرقام العربية، والفواصل، R-ENT-03 وR-BUD-03) | ✅ يحوّل ما يكتبه المستخدم إلى صيغة موحّدة | |
| **الصيغة الموحّدة المقبولة** | يرسلها | ✅ يتحقق منها فقط |

- **مبلغ المصروف والدورة:** `^\d{1,9}(\.\d{1,2})?$`. المصروف لازم أكبر من 0 وحتى 999,999,999، والدورة تقبل 0.
- **مبالغ الميزانية الشهرية:** `^-?\d{1,10}(\.\d{1,2})?$` أو `null`، مع حقل `isApprox` منفصل.
- **السبب:** قواعد الإدخال تخص الواجهة وتجربة الكتابة. والسيرفر يرفض أي شيء ليس بالصيغة الموحّدة، فلا يدخل مبلغ خاطئ أبداً.

### الصلاحيات في كل طلب

1. التحقق من JWT. وإذا غير صالح: `SYS-E001`.
2. المستخدم معطّل؟ `SYS-E009`.
3. الخدمة موقوفة (`services.enabled = false`)؟ `SYS-E003`.
4. **`GET`** يحتاج `can_read`، و**`POST` و`PUT` و`PATCH` و`DELETE`** تحتاج `can_write`. وإلا: `SYS-E002`.
5. السجل المطلوب ليس ملك المستخدم؟ **`SYS-E004` (غير موجود)**، وليس "ممنوع"، حتى لا نكشف أن السجل موجود.

### القفل التفاؤلي

- كل سجل قابل للتعديل يرجع حقل `version`.
- كل طلب تعديل (`PATCH`) **يرسل `version`** الذي عنده.
- إذا تغيّر السجل في مكان آخر: **`409` بالكود `SYS-E005`**، فيعيد Angular تحميل البيانات ويخبر المستخدم.

## 2. تسجيل الدخول والدعوات

### 2.1 طريقة الدخول: رمز بالإيميل (Email OTP)

| الخيار | المشكلة على الآيفون |
|---|---|
| رابط بالإيميل (Magic link) | ❌ الرابط يفتح في **Safari** وليس في التطبيق المثبت على الشاشة الرئيسية، فلا يدخل المستخدم |
| كلمة مرور | يعمل، لكنها كلمة مرور إضافية يحفظها المستخدم وتحتاج "نسيت كلمة المرور" |
| **رمز من 6 أرقام بالإيميل** ✅ | يكتب الرمز **داخل التطبيق نفسه**، بدون كلمات مرور |

- **مرة واحدة لكل جهاز:** Supabase يجدد الجلسة تلقائياً (refresh token)، فلا يُطلب الرمز كل مرة.
- **قفل Face ID** (passkeys) طبقة إضافية محلية فوق الجلسة، وتُفصّل في جلسة التخطيط 4.

### 2.2 الإعداد في Supabase Auth

| الإعداد | القيمة |
|---|---|
| Allow new users to sign up | **❌ مقفل** (بالدعوة فقط) |
| Email OTP | ✅ مفعّل، وطول الرمز 6 |
| Magic link | لا يُستخدم |
| SMTP | **خدمة إيميل خارجية مجانية** (مثل Resend أو Brevo)، لأن إيميل Supabase الافتراضي محدود جداً ومخصص للتجربة |
| قالب الإيميل | بالعربي، ويعرض الرمز `{{ .Token }}` بدل الرابط: [`docs/supabase/otp-email.html`](supabase/otp-email.html). **الخطة المجانية لا تسمح بتعديل القالب إلا مع SMTP خاص**، فيُطبّق مع SMTP |

**طُبّق (2026-10-31):** التسجيل مقفل، والرمز 6 أرقام وصالح 10 دقائق (`mailer_otp_exp: 600`)، وSite URL `https://abdullahaltaher.github.io/M-SAL2.0/`، والروابط المسموحة `localhost:4200` وGitHub Pages. **وطُبّق (2026-11-01، المرحلة 10):** SMTP عن طريق **Gmail المالك** بكلمة مرور تطبيق (Resend المجاني بدون دومين يرسل للمالك فقط)، والمرسل "ميزانية الشهر"، والقالب العربي بالرمز (`docs/supabase/otp-email.html`)، و`rate_limit_email_sent: 30` في الساعة (كان 2 مع إيميل Supabase). يطبّقها `scripts/apply-auth-email.mjs` الذي يشغّله المالك. **جُرّب:** وصل الرمز على الآيفون ودخل به.

### 2.3 خطوات الدعوة (SRV-009)

```
المدير (أنت)                     Spring Boot                       Supabase
    │ POST /admin/invitations          │                                  │
    │ { email }  ───────────────────→  │ 1. سجل invitations (PENDING)     │
    │                                  │ 2. Admin API: createUser ──────→ │ يُنشأ المستخدم
    │                                  │    (email_confirm = true،        │ بدون إرسال إيميل
    │                                  │     بدون كلمة مرور)              │
    │ ←───────────── 201 ────────────  │                                  │
    │                                                                     │
    │ تخبر صديقك: "افتح الرابط وادخل بإيميلك"                              │
```

- مفتاح **`service_role`** الخاص بـ Supabase موجود **في متغيرات بيئة الاستضافة فقط** (Render) كمتغير سري، ولا يصل لـ Angular أبداً.
- الدعوة تنتهي بعد **14 يوماً**.
- **إلغاء الدعوة** يحذف مستخدم Supabase إذا لم يدخل أبداً.

### 2.4 أول دخول

```
المستخدم                Angular                     Supabase              Spring Boot
   │ يكتب إيميله  ──→  signInWithOtp ────────────→ يرسل الرمز
   │                   (shouldCreateUser: false)    (فقط إذا المستخدم موجود)
   │ يكتب الرمز   ──→  verifyOtp ────────────────→ JWT
   │                   GET /api/v1/me ──────────────────────────────────→ │
   │                                                                     │ لا يوجد app_users؟
   │                                                                     │ ├ توجد دعوة PENDING لهذا الإيميل
   │                                                                     │ │   أو هو المدير الأول؟
   │                                                                     │ │   ← يُنشأ app_users + الأدوار
   │                                                                     │ │   ← ميزانية "الأساسي" بالقيم الافتراضية
   │                                                                     │ │   ← الدعوة تصير ACCEPTED
   │                                                                     │ └ لا توجد دعوة ← SRV-000-E001
   │ ←──────────────────────────────── بيانات المستخدم ──────────────────│
```

### 2.5 المدير الأول (أنت)

- قبل أول تشغيل، تضيف نفسك يدوياً في Supabase: **Authentication → Users → Add user** (بإيميلك فقط).
- متغير بيئة في الاستضافة (وفي `.env` محلياً): `MSAL_BOOTSTRAP_ADMIN_EMAIL=<إيميلك>`.
- أول دخول بهذا الإيميل **عندما لا يوجد أي مستخدم آخر** يأخذ الدورين `USER` و`ADMIN` بدون دعوة.

### 2.6 التحقق من JWT في Spring Boot

- عن طريق **Spring Security Resource Server** ومفاتيح Supabase العامة (JWKS):
  `https://<project>.supabase.co/auth/v1/.well-known/jwks.json`
- يتحقق من: التوقيع، وانتهاء الصلاحية، و`iss`، و`aud = authenticated`.
- **هوية المستخدم** = `sub`، و**الإيميل** = `email`.
- **تأكّدنا (2026-10-31):** المشروع يستخدم مفتاحاً غير متماثل **ES256** (JWKS فيه مفتاح واحد)، فلا نحتاج سراً مشتركاً (HS256). Spring Boot يتحقق بـ `jwk-set-uri` فقط.

## 4. الـ Endpoints حسب الخدمة

> كل المسارات تبدأ بـ `/api/v1`. **الأمثلة مختصرة.** الحقول المشتركة (`version`، و`createdAt`، و`updatedAt`) موجودة في كل سجل.
> **أسلوب المسارات:** الإنشاء والقوائم تحت الأب (`/budgets/{id}/accounts`)، والعمليات على سجل واحد بمساره المباشر (`/accounts/{id}`).

### SRV-000: الحساب والجلسة (خدمة جديدة)

> أُضيفت في هذه الجلسة، لأن كل Controller يحتاج كود خدمة، و`/me` لا ينتمي لأي خدمة أخرى. **USER: قراءة + كتابة.**

| الطريقة | المسار | الوصف |
|---|---|---|
| `GET` | `/me` | بيانات المستخدم وصلاحياته. **يُنشئ المستخدم في أول دخول** (2.4) |
| `PATCH` | `/me` | تعديل الاسم، أو المنطقة الزمنية، أو آخر ميزانية مفتوحة، أو وقت التذكير اليومي (`dailyReminderTime`) |
| `POST` | `/me/push-subscriptions` | تسجيل الجهاز للإشعارات (Web Push). انظر 9.5 |
| `DELETE` | `/me/push-subscriptions?endpoint=…` | إلغاء إشعارات الجهاز. انظر 9.5 |

**`GET /me` (الرد):**
```json
{
  "id": "3f2a…",
  "email": "abdullah@example.com",
  "displayName": "عبدالله",
  "timeZone": "Asia/Dubai",
  "today": "2026-11-11",
  "roles": ["USER", "ADMIN"],
  "services": {
    "SRV-001": { "read": true, "write": true },
    "SRV-006": { "read": true, "write": false },
    "SRV-009": { "read": true, "write": true }
  },
  "lastBudgetId": "b1…",
  "exportReminder": { "due": true, "days": 15, "never": false },
  "version": 3
}
```
- `services` تحتوي **فقط الخدمات المفعّلة والمسموحة**، وAngular يخفي الباقي.
- `exportReminder` حسب R-IO-01: آخر تصدير، أو تاريخ إنشاء الحساب إذا لم يصدّر أبداً.

### SRV-002: الميزانية الشهرية

| الطريقة | المسار | الوصف | القاعدة |
|---|---|---|---|
| `GET` | `/budgets` | قائمة الميزانيات ("الأشخاص") | |
| `POST` | `/budgets` | ميزانية جديدة بالقيم الافتراضية | R-BUD-06 |
| `GET` | `/budgets/{budgetId}` | الميزانية كاملة مع المجاميع | R-BUD-01 |
| `PATCH` | `/budgets/{budgetId}` | الاسم، واسم الشهر، ومسمى الراتب، والراتب، وآخر حساب | |
| `DELETE` | `/budgets/{budgetId}` | حذف مؤقت (يُرفض لآخر ميزانية) | R-BUD-06 |
| `POST` | `/budgets/{budgetId}/new-month` | شهر جديد | R-BUD-05 |
| `POST` | `/budgets/{budgetId}/groups` | مجموعة جديدة ببند فارغ | R-BUD-04 |
| `PATCH` | `/budget-groups/{groupId}` | اسم المجموعة | |
| `DELETE` | `/budget-groups/{groupId}` | حذف المجموعة وبنودها | R-BUD-04 |
| `POST` | `/budget-groups/{groupId}/items` | بند جديد | R-BUD-04 |
| `PATCH` | `/budget-items/{itemId}` | الاسم، والمبلغ، والتقريب، و"تم الصرف" | |
| `DELETE` | `/budget-items/{itemId}` | حذف البند | |

**`PATCH /budget-items/{itemId}` (الطلب):**

**`POST /budgets/{budgetId}/new-month`:** لا يحتاج جسماً. يمسح كل `isDone`، ويجعل `monthLabel` اسم الشهر الحالي بتوقيت المستخدم، ويسجّل البيانات قبل التغيير في `audit_log`.

### SRV-004: الحسابات

| الطريقة | المسار | الوصف | القاعدة |
|---|---|---|---|

## 5. الحفظ التلقائي

التطبيق القديم يحفظ تلقائياً بدون زر "حفظ" في الميزانية الشهرية. ونحافظ على نفس التجربة:

| المكان | الطريقة |
|---|---|
| **حقول الميزانية الشهرية** (الأسماء والمبالغ) | `PATCH` بعد **توقف الكتابة 600ms**، وعند الخروج من الحقل فوراً |
| **"تم الصرف"** | `PATCH` فوري عند الضغط |
| **نوافذ المصروف والدورة** | زر "حفظ" كما في القديم |

- **طلب واحد في نفس الوقت لكل سجل:** إذا كتب المستخدم أثناء حفظ سابق، ينتظر الطلب الجديد ثم يُرسل بالـ `version` الجديد. هكذا لا يتعارض المستخدم مع نفسه.
- **مؤشر الحالة:** "محفوظ ✓" بعد النجاح، و"لم يُحفظ" عند الفشل مع إعادة المحاولة، كما في التطبيق القديم.

## 6. صيغة ملف التصدير

**نفس صيغة M-SAL القديم (`schemaVersion: 3`)**، مع حقلين إضافيين:

```json
{
  "schemaVersion": 3,
  "app": "M-SAL2.0",
  "exportedAt": "2026-11-11T08:14:02Z",
  "currentId": "b1…",
  "profiles": [
    { "id": "b1…", "name": "عبدالله",
      "data": { "monthLabel": "…", "salaryLabel": "…", "salary": "~15000", "blocks": [ … ], "exp": { … } } }
  ]
}
```

- **المعرّفات** = UUID من M-SAL2.0.
- **ميزة:** الملف يُفتح أيضاً في **تطبيق M-SAL القديم**، فهو خطة رجوع لو احتجتها.
- **مطابقة المعرّفات عند الاستيراد:** لكل سجل في الملف، إذا `id` يطابق `id` سجل موجود لنفس المستخدم ← نفس السجل. وإلا إذا يطابق `legacy_id` ← نفس السجل. وإلا ← سجل جديد، ويُحفظ `id` الملف في `legacy_id`.

## 8. ملاحظات لمرحلة التنفيذ

1. **تنظيم Controllers:** Controller لكل خدمة، و`@ServiceCode` على مستوى الكلاس. مثال: `EntryController` ← `@ServiceCode("SRV-001")`.
2. **`@RestControllerAdvice` واحد** يحوّل كل الأخطاء إلى الشكل في 3.1، ويحوّل أخطاء قيود قاعدة البيانات (مثل تكرار الدورة) إلى أكوادها (`SRV-003-E004`).
3. **DTOs منفصلة** عن JPA Entities: `CreateEntryRequest`، و`EntryResponse`، ...
4. **التحقق:** Bean Validation (`@NotNull`، و`@Pattern`...) للصيغة، وقواعد العمل في Service.
5. **"اليوم"** من `Clock` قابل للحقن، حتى تختبر JUnit أي تاريخ (مثلاً 2026-11-11 في أمثلة R-CYC-04).
6. **Angular:** خدمة HTTP واحدة تضيف التوكن، وتحوّل الأخطاء، وتعيد المحاولة عند انقطاع الشبكة.
7. **اختبارات الـ API:** لكل endpoint: الحالة الناجحة، وكل كود خطأ في 3.3، و**طلب لسجل مستخدم آخر يرجع 404**.

## 9. ما تقرر أثناء التنفيذ (المرحلة 3)

> أُضيف 2026-11-01. هذه تفاصيل لم يحددها العقد أعلاه، وAngular يعتمد عليها. الاختبارات في `backend/src/test/java/com/abdullah/msal2/*ApiTest.java`.

### 9.1 طلبات PATCH
- **الحقل غير المرسَل لا يتغير، والحقل المرسَل بقيمة `null` يُمسح** إذا كان يقبل المسح: مبلغ بند الميزانية، والراتب (`"salary": null`)، وتاريخ الراتب القادم في الدورة. هذا يعمل في كل `PATCH` عن طريق `system/web/Patch`.
- **`version` إلزامي** في كل `PATCH`، وإلا `SYS-E006`.
- **الراتب** في `PATCH /budgets/{id}` كائن واحد: `"salary": { "amount": "15000", "isApprox": false }`.
- **المبالغ والتواريخ في الطلبات نصوص** (`"46.25"`، و`"2026-11-11"`)، حتى يأخذ كل خطأ كوده: تاريخ مصروف غير صالح `SRV-001-E004`، وتاريخ دورة غير صالح `SRV-003-E001`. ونوع المصروف `"EXPENSE"` (الافتراضي) أو `"INCOME"`.

### 9.2 الردود
| الطلب | الرد |
|---|---|
| `POST /budgets`، و`PATCH /budgets/{id}`، و`POST .../new-month` | الميزانية كاملة مع المجاميع |
| `POST /budgets/{id}/groups`، و`PATCH /budget-groups/{id}` | المجموعة مع بنودها ومجاميعها |
| `POST /budget-groups/{id}/items`، و`PATCH /budget-items/{id}` | البند فقط (Angular يحسب المجاميع أثناء الكتابة، و`GET /budgets/{id}` هو المرجع) |
| كل `DELETE` | `204` بدون جسم، عدا `DELETE /budgets/{id}/entries/deleted` الذي يرجع `{ "purged": 3 }` |
| `GET .../entries/last-expense` | `204` إذا لا يوجد مصروف بعد |
| `GET .../entries/suggestions` | `{ "suggestions": [ ... ] }` |
| `POST .../entries`، و`PATCH /entries/{id}`، و`restore`، و`duplicate` | المصروف مع `cycleKey` (الدورة التي وقع فيها، أو `none`) |
| `PUT .../categories/order` | الفئات بالترتيب الجديد |
| `GET /admin/audit-log` | `{ items, page, size, total }`، و`size` حتى 100. **بدون `before_data` و`after_data`** |

- **`cycleKeys`** في `/home`: `none` أولاً إذا توجد مصاريف قبل أول دورة أو لا توجد دورات أصلاً، ثم الدورات من الأقدم.
- **`progress`** رقم (`0.3433`)، وكل المبالغ الأخرى نصوص.
- **`changes`** في الإحصاءات: أكبر 5 فقط (R-STA-05).
- **إنشاء ميزانية** يجعلها المفتوحة (`app_users.last_budget_id`)، و**حذفها** ينقل المفتوحة لأول ميزانية باقية.
- **أول دخول** يُنشئ ميزانية "الأساسي" كاملة (R-BUD-06).

### 9.3 الأمان والحدود
- **سجل مستخدم آخر، أو سجل تحت ميزانية محذوفة** ← `404 SYS-E004` في كل endpoint. و**ربط سجل بسجل مستخدم آخر** في جسم الطلب يأخذ كود الحقل: فئة `SRV-001-E002`، وحساب `SRV-001-E005`. `IsolationTest` يجرّب 38 طلباً.
- **تحديد الطلبات:** 120 في الدقيقة لكل مستخدم، و10 لـ `POST /admin/invitations` (`@StrictRateLimit`). في الذاكرة، لسيرفر واحد.
- **حجم الطلب:** أكثر من 1 ميغابايت ← `400 SYS-E006`.
- **Swagger:** في ملف `dev` فقط (`http://localhost:8080/swagger-ui.html`)، و`docker-compose.yml` يشغّله افتراضياً. خارج `dev` المسارات `404`.
- **الدعوات:** الإيميل يُقصّ ويُصغّر قبل الفحص. لا يمكن إيقاف `SRV-000` أو `SRV-009` (`SYS-E006`)، حتى لا يُقفل المدير خارج التطبيق.
- **حجم ملف الاستيراد:** أكثر من 5 ميغابايت ← `413 SRV-007-E003` (`RequestSizeFilter` قبل القراءة، و`spring.servlet.multipart`)، و`POST /imports` عليه `@StrictRateLimit`.

### 9.4 الاستيراد والتصدير (SRV-007، المرحلة 6)
- **رد المعاينة** فيه أيضاً `current` (نفس الأعداد لبيانات المستخدم الآن، لجدول "عندك الآن")، و`target` (`{id, name}`، الميزانية التي يدخلها ملف `SINGLE`: المفتوحة). ورسائل التحذيرات بصيغة "مصاريف بفئة غير موجودة، ستُربط بفئة «أخرى» (2)".
- **`POST /imports?mode=MERGE|REPLACE`** يرجع سجل الاستيراد `{id, fileName, mode, counts, warnings, createdAt}`، و`GET /imports` آخر 50 منها (بدون الملف).
- **ملف `SINGLE`** يدخل الميزانية المفتوحة، و`REPLACE` له لا يلمس مصاريفها (مثل القديم). و`REPLACE` لملف `STATE` يحذف (مؤقتاً) الميزانيات غير الموجودة في الملف.
- **التصدير** يضيف `code` للفئات الافتراضية (`cat_food`)، والقديم يحتفظ بالحقول غير المعروفة، فلا يضيع `code` عند تصدير ثم استيراد. والفئة الافتراضية تُطابَق أيضاً بالـ `code`.
- **اسم ملف التصدير** يحسبه Angular من `today` في `/me` (`Content-Disposition` لا يصل عبر CORS بدون `expose`).
- **الحذف الفعلي في الاستبدال** (المجموعات والبنود، والحسابات والفئات والمصاريف إذا الملف فيه قسم مصاريف) نسخته في `audit_log.before_data`: ملف تصدير كامل قبل الاستيراد (R-IO-05).

### 9.5 التذكير اليومي والإشعارات (SRV-000، المرحلة 7)
- **`GET /me`** فيه أيضاً `dailyReminderTime` (`"21:00:00"` بتوقيت المستخدم، أو `null` = متوقف)، و`pushPublicKey` (مفتاح VAPID العام للاشتراك، أو `null` إذا السيرفر بدون مفاتيح).
- **`PATCH /me`** يقبل `dailyReminderTime` (`"HH:mm"`)، و`null` يوقفه. وقت غير صالح ← `SYS-E006`.
- **`POST /me/push-subscriptions`** جسمه هو `PushSubscription.toJSON()` من المتصفح (`{endpoint, keys: {p256dh, auth}}`)، ويرد `204`. الجهاز نفسه (نفس `endpoint`) يُسجَّل مرة واحدة، ويصير لآخر مستخدم دخل عليه.
- **`DELETE /me/push-subscriptions?endpoint=…`** يحذف جهاز المستخدم فقط (`204` دائماً، وجهاز مستخدم آخر لا يُلمس).
- **`SRV-000-E003`** (400) "اشتراك الإشعارات غير صالح.": `endpoint` ليس `https` على خدمات إشعارات المتصفحات المعروفة (Apple، وGoogle FCM، وMozilla، وMicrosoft)، أو المفاتيح غير صالحة. **السبب:** السيرفر يرسل للـ `endpoint`، فلا يُسمح بأي عنوان آخر (حماية من SSRF).
- **المهمة المجدولة** كل دقيقة: المستخدم الذي جاء وقت تذكيره (بتوقيته) يُفحص **مرة واحدة في اليوم** (`app_users.last_reminder_on`)، ويُرسل له فقط إذا لم يسجّل **مصروفاً** (وليس دخلاً) بتاريخ اليوم. وإذا كان السيرفر متوقفاً وقت التذكير، يُرسل خلال الساعة التالية. الجهاز الذي ألغى الاشتراك (`404`/`410`) يُحذف.
- **الإرسال** بـ JDK فقط (`push/WebPush`: VAPID وتشفير `aes128gcm`)، بدون مكتبة إضافية، والإشعار بصيغة Angular Service Worker (`notification` مع `onActionClick` يفتح المصاريف)، والرقم على الأيقونة من `public/msal-sw.js`.
