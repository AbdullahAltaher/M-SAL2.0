# النسخ الاحتياطي

> المرجع: `PLAN.md` القسم 12. هذا الملف عن **كيف تعمل النسخ، وكيف تُستعاد**. لا أسرار هنا.

## كيف تعمل

| | |
|---|---|
| **متى** | كل يوم الساعة 03:30 بتوقيت دبي، ويمكن تشغيلها يدوياً (Actions ← Daily backup ← Run workflow) |
| **أين** | المستودع **الخاص** `AbdullahAltaher/M-SAL2.0-backups`، في مجلد `backups/`. **ولا شيء منها في المستودع العام** `M-SAL2.0` |
| **ماذا** | `pg_dump` لـ schema `msal` كاملة (كل الجداول والبيانات) من Supabase، بدون owners ولا صلاحيات |
| **التشفير** | `gzip` ثم `age` بالمفتاح **العام** للمالك. المفتاح **الخاص** وحده يفتحها، وهو عند المالك فقط (ليس في GitHub) |
| **الاحتفاظ** | آخر 60 يوماً، ونسخة أول كل شهر للأبد |
| **القالب** | `ops/backup/backup.yml` في هذا المستودع، ونسخته العاملة في `.github/workflows/backup.yml` في المستودع الخاص |
| **التكلفة** | مجاني: دقيقة تقريباً يومياً من 2,000 دقيقة شهرياً للمستودعات الخاصة |

**الإعداد مرة واحدة** (المالك يشغّله بنفسه، القاعدة 16):
```bash
node scripts/setup-backups.mjs
```
يصنع زوج المفاتيح، ويحفظ **الخاص** في `~/M-SAL2.0-backup-key.txt` (لا يُطبع)، ويضع في المستودع الخاص: السر `DB_PASSWORD`، والمتغيرات `DB_HOST` و`DB_USER` و`AGE_RECIPIENT` (المفتاح العام).

> **المفتاح الخاص:** احتفظ بنسخة منه خارج الكمبيوتر (مدير كلمات المرور، أو USB). **إذا ضاع، لا يمكن فتح أي نسخة.** وإذا تسرّب، اصنع زوجاً جديداً (احذف الملف وشغّل السكربت)، فالنسخ الجديدة تُشفّر بالجديد، والقديمة تحتاج القديم.

> **إذا تغيّرت كلمة مرور قاعدة البيانات:** حدّثها في `.env` وشغّل السكربت مرة ثانية (يستخدم نفس المفتاح).

## التحقق من نسخة (بدون لمس أي شيء)

نزّل ملف نسخة من المستودع الخاص، ثم:
```bash
node scripts/restore-backup.mjs <msal-YYYY-MM-DD.sql.gz.age>
```
يفك التشفير ويحمّلها في Postgres 17 مؤقت في Docker، ويطبع عدد الصفوف فقط، ثم يحذف الحاوية. لا يلمس Supabase ولا القاعدة المحلية.

## الاستعادة الفعلية (عند كارثة فقط)

**القاعدة 3:** Flyway وحده يغيّر الجداول. الاستعادة تعيد **نفس** الجداول والبيانات، فالخطوات بالترتيب وبموافقة المالك:
1. أوقف السيرفر في Render (Suspend) حتى لا يكتب أحد أثناء الاستعادة.
2. خذ نسخة من الحالة الحالية أولاً (شغّل Daily backup يدوياً).
3. فك التشفير محلياً: `age -d -i ~/M-SAL2.0-backup-key.txt msal-YYYY-MM-DD.sql.gz.age | gunzip > restore.sql` (لا يُرفع هذا الملف لأي مستودع).
4. في Supabase: احذف schema `msal` القديمة (`drop schema msal cascade`)، ثم حمّل `restore.sql` بـ `psql` عبر Session pooler. الملف يحتوي جدول Flyway (`flyway_schema_history`)، فيعرف Flyway أن الـ migrations مطبقة.
5. شغّل السيرفر، وتأكد من `/actuator/health` ومن الأرقام، ثم احذف `restore.sql`.
