# خطة M-SAL2.0 الكاملة

> آخر تحديث: 2026-10-31. هذه الخطة نتيجة جلسة التخطيط الأولى، وتُحدَّث مع كل جلسة.

## 1. الهدف والمبادئ

**الهدف:** إعادة بناء تطبيق الميزانية **بنفس الفكرة وطريقة العمل**، ببنية قوية ومنظمة، وبنفس تقنيات الدوام. والتطبيق مهيأ لاستخدام الأصدقاء والأهل مستقبلاً.

**المبادئ:**
1. **M-SAL الحالي لا يُمس**، ويستمر يعمل حتى يكتمل الانتقال.
2. **المطابقة أولاً ثم التحسين**: الشاشات تطابق الحالية، والتحسينات بعد ذلك.
3. **كل مرحلة تنتهي بنسخة تعمل.**
4. **بدون مصاريف إضافية**: حوالي 5 دولار شهرياً فقط، وحد أقصى 10.
5. **البيانات في Supabase فقط**، والسيرفر لا يحفظ شيئاً، فتقدر تنقله لأي مكان.

### المنطقة والإعدادات (تقررت 2026-10-31)

- **Supabase:** مشروع `M-SAL2.0` في **Southeast Asia (Singapore)**. **Data API معطّل** (لا API عام على قاعدة البيانات)، وGitHub غير مربوط، ونوع Postgres الافتراضي.
  - **أُنشئ:** 2026-10-31، والحجم NANO (المجاني).
  - **Project ref:** `bzdzveckpxmmdoqcfewv`، والرابط `https://bzdzveckpxmmdoqcfewv.supabase.co`. هذا **ليس سراً**، فهو يظهر في Angular أصلاً.
  - "Last migration" في لوحة Supabase ستبقى "No migrations"، لأن Flyway يسجّل في جدوله الخاص `msal.flyway_schema_history`. و"Last backup" ستبقى فارغة في الخطة المجانية، ونسخنا الاحتياطية من GitHub Actions (القسم 12).
- **Railway:** يجب أن يكون السيرفر في **Singapore** أيضاً، حتى يكون قريباً من قاعدة البيانات.
  - **الحساب لم يُنشأ بعد، عن قصد:** التجربة المجانية تبدأ من التسجيل، فيُنشأ في المرحلة 8 فقط.
  - **ملاحظة 2026-10-31:** التسجيل في Railway كان **موقوفاً مؤقتاً** بعد حادثة عندهم في 21 أكتوبر. يُتأكد منه في المرحلة 8. وإذا ما زال موقوفاً، البديل بنفس صورة Docker بدون تغيير الكود: **Fly.io** (حوالي 3–5 دولار) أو **Oracle Cloud Free** (القسم "لماذا Railway؟").
- **supabase-js في Angular** يُستخدم **لتسجيل الدخول فقط**، ولا يتأثر بتعطيل Data API. كل البيانات تمر عبر Spring Boot.

### لماذا Railway؟

- **Render:** الخطة المجانية تنام بعد 15 دقيقة بدون طلبات، ويأخذ التشغيل من جديد حوالي دقيقة. وسيرفر Starter (حوالي 7 دولار) فيه 512MB ذاكرة فقط، وهذا ضيق على Spring Boot.
- **Railway Free:** حد 0.5GB ذاكرة، ورصيد دولار واحد شهرياً بعد التجربة، وهذا لا يكفي لسيرفر يعمل طوال الشهر.
- **Railway Hobby:** ✅ 5 دولار كحد أدنى تشمل 5 دولار استهلاك، والذاكرة حتى 48GB لكل خدمة، ولا ينام.
- **Oracle Cloud Free:** بديل مجاني، لكنه يحتاج إدارة كاملة للسيرفر، وقد يسترجع السيرفرات الخاملة. يبقى خطة بديلة، لأن Docker يسمح بالانتقال بسهولة.

## 5. أكواد الخدمات

| الكود | الخدمة | من يدخلها |
|---|---|---|
| SRV-000 | الحساب والجلسة (`/me`) | USER |
| SRV-001 | المصاريف | USER |
| SRV-002 | الميزانية الشهرية | USER |
| SRV-003 | دورات الراتب | USER |
| SRV-004 | الحسابات | USER |
| SRV-005 | الفئات | USER |
| SRV-006 | الإحصاءات | USER |
| SRV-007 | الاستيراد والتصدير | USER |
| SRV-008 | الإيصال | USER |
| SRV-009 | إدارة المستخدمين والدعوات | ADMIN فقط |
| SRV-010 | العائلة (مستقبلاً) | USER |

**أين تُستخدم الأكواد:**
- **قاعدة البيانات:** جدول `services` فيه الكود والاسم وحالة التفعيل، فتقدر توقف أي خدمة بدون تعديل كود.
- **الكود:** `@ServiceCode("SRV-001")` على كل Controller.
- **الصلاحيات:** جدول `role_services` يحدد أي دور يدخل أي خدمة، قراءة فقط أو قراءة وكتابة.
- **السجلات:** كل سطر log يحمل كود الخدمة ورقم المستخدم (MDC).
- **سجل النشاط:** جدول `audit_log` يسجل كل عملية مهمة مع كود الخدمة.
- **أكواد الأخطاء:** بصيغة `SRV-001-E001`.
- **Angular:** إخفاء الأقسام غير المسموحة ومنع فتح صفحاتها.

## 6. المستخدمون والأمان

| الحماية | التفاصيل |
|---|---|
| **تسجيل الدخول** | **رمز من 6 أرقام بالإيميل** (Email OTP) عبر Supabase Auth، مرة واحدة لكل جهاز. Supabase يعطي JWT، وSpring Security يتحقق منه في كل طلب. التفاصيل في [API.md](API.md) القسم 2 |
| **إيميلات الدخول** | خدمة SMTP خارجية مجانية (مثل Resend أو Brevo)، لأن إيميل Supabase الافتراضي محدود جداً |
| **بالدعوة فقط** | التسجيل المفتوح مقفل، ولا أحد يدخل إلا بدعوة عبر SRV-009 |
| **عزل البيانات** | كل جدول فيه `user_id`، والهوية تؤخذ **من التوكن فقط** |
| **اختبارات العزل** | اختبارات تتأكد أن أي مستخدم لا يرى ولا يعدّل بيانات غيره |
| **الأدوار** | USER وADMIN، مرتبطة بأكواد الخدمات |
| **تحديد الطلبات** | rate limiting يحمي من الطلبات الكثيرة |
| **قفل Face ID** | داخل التطبيق عن طريق passkeys (WebAuthn) |
| **HTTPS** | في كل مكان |

## 7. قاعدة البيانات

> **التصميم الكامل:** [DATABASE.md](DATABASE.md) (جلسة التخطيط 2)، وفيه الأعمدة والعلاقات والقيود ومسودة ملفات Flyway.

**القواعد:**
- كل الجداول في schema اسمه **`msal`**، مع **RLS مفعّل**، حتى لا تُفتح عبر API العام في Supabase.
- كل سجل له **UUID** (عدا جداول المرجع و`audit_log`).
- **Flyway وحده** يغيّر الجداول.
- **ممنوع** تعديل الجداول من لوحة Supabase.
- المبالغ بنوع `numeric(12,2)`.
- **الحذف حسب النوع:** مؤقت للمصاريف والميزانيات، وأرشفة للحسابات، وإخفاء للفئات، وحذف فعلي مع نسخة في `audit_log` للمجموعات والبنود والدورات.
- كل جدول فيه `created_at` و`updated_at` و`version`.

**الجداول:**
```
── النظام ──────────────────────────────
services            أكواد الخدمات
roles               الأدوار
role_services       صلاحيات كل دور على كل خدمة
app_users           المستخدمون (id = sub من JWT)
user_roles          أدوار كل مستخدم
invitations         الدعوات (SRV-009)
audit_log           سجل النشاط الدائم
imports             ملفات الاستيراد الأصلية (SRV-007)

── الميزانية (SRV-002) ─────────────────
budgets             الميزانيات ("الأشخاص" في التطبيق الحالي)
budget_groups       المجموعات
budget_items        البنود

── المصاريف ────────────────────────────
category_templates  الفئات الافتراضية الـ 20 (مرجع)
accounts            الحسابات        (SRV-004)
categories          الفئات          (SRV-005)
salary_cycles       دورات الراتب    (SRV-003)
entries             المصاريف والدخل (SRV-001)

── مستقبلاً ────────────────────────────
households, household_members   (SRV-010)
budget_months                   (سجل الأشهر، إذا احتجناه)
```

## 8. السيرفر (Spring Boot)

**النوع:** modular monolith، أي سيرفر واحد مقسّم إلى وحدات.

```
backend/src/main/java/com/abdullah/msal2/
├── system/        الخدمات، والصلاحيات، و@ServiceCode، وaudit_log، والسجلات
├── users/         المستخدمون والدعوات       (SRV-009)
├── expenses/      المصاريف                  (SRV-001)
├── budget/        الميزانية الشهرية         (SRV-002)
├── cycles/        دورات الراتب              (SRV-003)
├── accounts/      الحسابات                  (SRV-004)
├── categories/    الفئات                    (SRV-005)
├── stats/         الإحصاءات                 (SRV-006)
├── importer/      الاستيراد والتصدير        (SRV-007)
└── receipt/       الإيصال                   (SRV-008)

backend/src/main/resources/db/migration/
├── V1__create_system.sql
├── V2__seed_system.sql
├── V3__create_budget.sql
├── V4__create_expenses.sql
├── V5__seed_category_templates.sql
└── V6__create_imports.sql
```

- **كل وحدة:** Controller ← Service ← Repository، مع DTOs.
- **الحسابات المهمة** في Java مع اختبارات JUnit (انظر `BUSINESS_RULES.md`).
- **اختبارات M-SAL الحالية** (`test/*.test.js`) تتحول إلى JUnit حتى نتأكد أن النتائج مطابقة.
- **الذاكرة:** `-XX:MaxRAMPercentage=75`، مع Java 21 وvirtual threads.

## 12. النسخ الاحتياطي

- **يومياً** عن طريق GitHub Actions: نسخة كاملة من قاعدة البيانات.
- **مشفّرة** قبل الحفظ، لأنها بيانات مالية.
- **في مستودع خاص منفصل** اسمه `M-SAL2.0-backups`، لأن مستودع `M-SAL2.0` **عام**. مهمة النسخ تعمل من المستودع الخاص وتحفظ النسخ فيه (ضمن 2,000 دقيقة مجانية شهرياً). **لا شيء من النسخ الاحتياطية في المستودع العام أبداً.**
- **إلزامي قبل** أن يستخدم التطبيق أي شخص غير المالك.
- كل مستخدم يقدر يصدّر بياناته بنفسه (SRV-007).

## 17. جلسات التخطيط القادمة

كل جلسة تعتمد على التي قبلها:

```
1. قواعد العمل    ← ماذا يفعل التطبيق بالضبط؟
       ↓
2. قاعدة البيانات ← أين نحفظ البيانات؟
       ↓
3. الـ API        ← كيف تتكلم الواجهة مع السيرفر؟
       ↓
4. الشاشات        ← ماذا يرى المستخدم؟
```

| # | الجلسة | المحتوى | النتيجة | الحالة |
|---|---|---|---|---|
| 1 | **قواعد العمل** | استخراج كل القواعد والحسابات من كود M-SAL: الدورات، و"كم تقدر تصرف اليوم"، وتغيير تاريخ الدورة، والمتبقي في الميزانية، والحذف والاستعادة، والإحصاءات، والاستيراد. كل قاعدة بالعربي + مثال بالأرقام + الدالة المصدر | `docs/BUSINESS_RULES.md`، مرجع اختبارات JUnit | ✅ مكتملة |
| 2 | **قاعدة البيانات** | الأعمدة والأنواع، والعلاقات، والقيود، والفهارس، وخريطة نقل كل حقل من JSON القديم إلى الجداول | `docs/DATABASE.md`: مسودة ملفات Flyway، ورسم العلاقات | ✅ مكتملة |
| 3 | **الـ API** | endpoints لكل خدمة، وشكل الطلب والرد، وأكواد الأخطاء `SRV-xxx-Eyyy`، وقواعد التحقق | `docs/API.md`: الـ API كعقد بين Angular وSpring Boot | ✅ مكتملة |
| 4 | **الشاشات** | كل شاشة في M-SAL وما يقابلها في Angular، والتنقل، والمكونات المشتركة، والـ API وكود SRV لكل شاشة | `docs/SCREENS.md`: خريطة الشاشات والمكونات | ✅ مكتملة |
